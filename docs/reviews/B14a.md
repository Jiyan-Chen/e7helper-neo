## 开工调研（2026-10-22）
### e7rtabot Live Draft（在浏览器里逐步走了一遍）
| 步骤 | 内容 |
|---|---|
| 准备 | 模式（普通 / 瘋狂徵召）、我方段位、对方段位（挑战者及以下 / 优胜者 / 战神 / 王者 / 传说）、开战规则（优胜者以上：攻击 / 防御 / 抵抗 / 特殊）、先后手、我的英雄池（登录后配置；没配置的英雄按最常见配装） |
| 预禁 | 双方各 2 名（可以重复），英雄网格按热度排，可以「固定」常用的预禁组合 |
| 选秀 | 1-2-2-2-2-1，第 3 手是保护位（不能被后禁）；每个空位 1 个主推荐 + 2 个备选（分数≈胜率）；实时胜率；已选英雄显示速度估计和「先手概率」；可撤销 |
| 后禁 | 双方各禁对方 1 名（第 3 手除外）。推荐 = 4×4 胜率矩阵（我禁谁 × 对方禁谁）取 maximin（接口直接返回 `win_matrix` / `p_first_matrix`） |
| 结果 | 最终胜率、谁先手的概率、站位建议（位置 1–4，「推荐」/「灵活」） |

- 模型：服务器端深度学习，「一个模型估胜率、另一个在选秀树上搜索」，只覆盖约 120 名常用英雄，每个平衡补丁后重训（本赛季 28 万场）。
- 其他页面：Quick Analysis（两队直接对比胜率和先手）、Hero Stats（胜 / 选 / 预禁 / 后禁率、场数、伤害评级、克制 / 被克 / 搭档（带分数）、套装 + 神器组合胜率、属性分布）。

## 开战规则的验证结论（用户意见 3）
- **海外**：对局带 `opening_rule_title`（类别 `rta_openingrule_category_N`）和 `opening_rule_desc_tid`（具体规则）。采到的 3.73 万场本赛季对局（较低一方都是优胜者以上）**每场都有**，四条规则各约 25%，同一名玩家连续几局的规则都不一样 → **每局随机**，不是按天轮换。本赛季四条：`soulburn_dmg_up` 攻击 9208、`heal_shield_up` 防御 9339、`resist_up_50` 抵抗 9331、`dodge_down` 特殊 9392（2026-10-23 的数据）。
- **国服**：11.6 万场（含 2.7 万场优胜者、2.0 万场王者、4.4 万场战神）**一场都没有**这两个字段。国服接口还没加，或者国服版本还没上开战规则；用户说国服马上同步国际服，同步后 `e7helper rta probe -s cn` 再看一次。B14b 里开战规则作为输入，国服记为「未知」。
- 海外有一方低于优胜者的对局（采到 67 场，挑战者 / 大师对优胜者）两个字段都是占位符 `_`，解析成「没有规则」（数据可视化时发现，补了测试，RTA 测试变成 53 个）。
- 对照表在 `rules.OPENING_RULES`（名字和说明按官方「2026 夏季赛季图表」公告）；没登记的规则按类别给名字（类别 1 攻击、2 防御、4 抵抗、6 特殊；3 / 5 还没见过）。

## 后续块的设计草案（开新块时再细化）
### B14b 胜率 / 选人模型
- **共用特征编码** `core/rta/encode.py`：训练和运行用同一份，另存一个 parity 样例（几十个局面 + 期望输出）防止两边对不上。
- **样本**：每场 12 个局面。n = 0…9（选了 n 手后，视角 = 下一手的一方；胜率标签 = 这一方是否赢；选人标签 = 第 n+1 手，两手回合的第一手用两名英雄各 0.5 的软标签）；n = 10（选完、后禁前）和 n = 11（后禁后，带被禁标记）只训胜率。预禁做成「我方 / 对方」两个多热向量加进上下文。两服数据直接合并（用户意见）；开战规则作为输入，国服记为「未知」。
- **切分**：按日期，最后 7 天测试、再前 7 天验证；同一场的所有局面在同一份。
- **网络**（约 10 万参数，CPU 能训）：最多 11 个 token（上下文 + 10 手），英雄嵌入 d=64 + 我方 / 对方 + 保护 / 被禁；上下文 = 双方段位档、第几手、先手、轮到谁、开战规则、预禁。2 层 Transformer、4 头；胜率头；选人头和英雄嵌入共享权重。词表 = 选过 ≥ 30 次的英雄，其余 UNK。
- **反对称做进模型**：`v = σ((g(s) − g(交换双方的 s)) / T)`，保证双方胜率加起来是 1。
- **基线**：只看段位 + 先手；英雄强度逻辑回归；反对称因子分解机（强度 + 搭档 + 对位克制）。Transformer 在 n=11 的 log loss 至少好 0.002、校准不差才用它，否则随包因子分解机（numpy 推理）。
- **导出**：手写注意力，`torch.onnx.export`（opset 18，不行退 17），批次维度动态；onnxruntime 引擎已经有。训练用的 torch 放新依赖组 `train`，只在开发机装，spec 的 `excludes` 加 torch / onnx。
- 预期：只看选秀的胜负信号不强（AUC 大概 0.58–0.65），推荐之间差距小时要明说。

### B14c 选秀推荐（用户：每个空位 5–8 名，时间可以放宽）
- 一层：所有可用 ∩ 英雄池（没勾不限制）的英雄各算一次；威胁集（对手加上哪名英雄我方胜率掉得最多）每次只算一遍。
- 候选取一层前 12–16；对手回应 = 选人头前几名 ∪ 威胁前几名；两手回合按对评估；分数 = 最差和按选人头加权的期望各一半；时间预算 2 秒，可以再往下看一层（我方下一轮）。
- 每个空位给 5–8 名：胜率、和第一名的差距、最可能的对手回应；差距 < 1% 时标「差距不明显」。
- 预禁：候选 8 名两两组合，用选人头批量模拟（共用随机数），≤ 5 秒。后禁：4×4 矩阵 maximin + 按对手常见后禁的期望 + 混合策略。

### B14d 分析功能
- 先手概率：出手时间 = (100 − 开局随机行动条) / 速度，速度来自英雄池（玩家填的）或 Fribbels 配装库的分位数（国服战绩站只有相对档位），蒙特卡洛。
- 站位：每名英雄的站位分布（采集的 `position`），24 种排法取似然最大，置信高的标「推荐」。站位 1–4 对应游戏里哪个格子，B14f 截图时核对。
- 快速分析：两队 → 胜率（5v5 走后禁矩阵）、每名英雄的贡献、克制 / 搭档对。
- 英雄统计：官方 `getPopularHero` + 我们的统计（预禁率、先手选率、克制 / 搭档带数字、套装 + 神器组合胜率、伤害）。
- 英雄池接口（`<数据目录>/modules/rta_draft/pool.json`）。
