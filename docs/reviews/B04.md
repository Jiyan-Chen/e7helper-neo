### 配置 `SecretShopConfig`
| 字段 | 默认 | 说明 |
|---|---|---|
| `targets` | 誓约书签（184,000，图标 `item/covenant`）、神秘奖牌（280,000，图标 `item/mystic`） | 名字**或**图标对上就算目标；设了 `price` 时价格读数必须一致 |
| `max_refreshes` | 10 | 最多刷新次数 |
| `skystone_budget` | 30 | 本次最多花多少天空石 |
| `skystone_keep` | 0 | 刷新后天空石不能低于此数 |
| `gold_floor` | 0 | 买完后金币不能低于此数；所有目标都设了价格、而且金币连最便宜的都买不起时，也停止刷新 |
| `refresh_cost` | 3 | 「立即更新」旁的消耗读数与此不符就停止 |
| `max_failures` | 3 | 连续失败次数上限 |
| `dry_run` | **true** | 只识别和决策，不点购买和刷新。实跑要显式传 `false` |
| `probe_dialogs` | false | dry-run 时打开购买/刷新确认框核对内容，然后点取消 |

### 流程与安全规则
1. `wait_scene(lobby/secret_shop)`，在大厅就 `tap_until("lobby/secret_shop", "secret_shop")`。
2. 每页：
   - 从大厅进店时列表在顶部；任务开始时本来就在商店里（可能被滑动过）才先滑到顶。游戏刷新后列表会自动回到顶部，这时也不滑。
   - 每次扫描前等**列表区域**停稳（右侧列表缩略图连续 0.25 秒变化 < 1，每 0.08 秒查一次），左侧人物的待机动画不参与判断。
   - 扫描顶部 → 滑到底 → 扫描底部。一次滑动（y 760→210）就能到底；名字被顶栏挡住的半行跳过。
3. 遇到目标商品，`decide` 依次核对：价格读得出、价格旁是金币图标、价格与预期一致、买完不低于金币下限。
   - 读金币用的是当时的新读数。
   - 有一项不过就不买，并在日志里写明原因。
4. 购买：
   - 点「购买」→ 等 `shop_buy` 弹窗且 `dialog/buy_ok` 完全显示 → 核对确认框里的名字和价格与列表这一行一致，不一致就点取消；
   - 稍等 0.15 秒后点「购买」确认 → 轮询顶栏直到金币变化 → **按金币读数差判断**。
5. 刷新：
   - 先检查次数、预算、保底、消耗读数；
   - 点「立即更新」→ 等 `shop_refresh` 弹窗（文字模板完全显示）→ 稍等 0.15 秒后点确认 → 轮询顶栏直到天空石变化 → **按天空石读数差判断**。
   - 「操作前」读数直接用上一次核对后的读数，不再单独读。
6. 读数差的处理：
   - 等于预期：计数成功；
   - 为 0：轮询 6 秒仍没变化才算失败，**不计数**；
   - 其他值（例如重试导致扣两次）：抛出 `ShopAnomaly`，任务记为 failed 并保存调试截图，统计里记实际花费。
   - 轮询途中出现网络异常立即点重试；确认框没关掉（点击被吞）或其他弹窗，先等 1 秒让它自己消失，再交给内置规则（点取消 / 返回键）。
7. 顶栏读数：连续两帧一致才采用。买完后金币数字会滚动约 0.4 秒，实测第一帧读到的是中间值。
8. 同一页同一件商品最多尝试 2 次；买到或决定不买之后不再处理。连续失败 `max_failures` 次就停止（任务仍算 succeeded）。
9. 无论正常停止、异常、急停还是超时，`finally` 里都会写统计。

### 新注册的弹窗（`setup()`，放在内置弹窗前面）
| 名称 | 判定 | 自动关闭 |
|---|---|---|
| `shop_refresh` | `secret_shop:dialog/refresh_text` + `dialog/cancel` + `dialog/confirm` | 点取消 |
| `shop_buy` | `secret_shop:dialog/buy_title` + `dialog/cancel` | 点取消 |

任务自己打开确认框，自己点确认。`wait_scene` / `dismiss_popups` 碰到这两个弹窗只会点取消，所以点确认时如果点击被吞、确认框还留着，后续流程会把它取消掉，不会重复确认。

### 审核意见后的提速（用户：3 次刷新用 36.8 秒太慢）
耗时分析（逐帧实测 + fixtures 计时）：
| 环节 | 原来 | 原因 | 改为 |
|---|---|---|---|
| 刷新确认框判定 | 每帧约 620ms | `shop_refresh` 用 OCR 文字区分 | 文字模板 `dialog/refresh_text`，约 20ms |
| 滑到底后等待 | 约 3 秒 | 点击后随机等待 0.25–0.55 秒 + 整屏静止 0.5 秒 + 0.3 秒轮询粒度 | 等列表区域停稳（实测滑动结束后约 0.7 秒停住），约 1.3 秒 |
| 扫描前的 `wait_scene` | 每屏 0.6–0.9 秒 | 每次都要求整屏静止 0.5 秒 | 同上，列表已停稳时约 0.3 秒 |
| 刷新前读顶栏 | 约 0.4 秒 | 两帧间隔 0.3 秒 | 复用上一次核对后的读数 |
| 点确认后核对 | 整屏静止 + 读两帧；读数没变还要隔 1.5 秒复读 | | 轮询顶栏直到读数变化，再读两帧（间隔 0.15 秒） |

## 过程中发现的问题与决策
1. **顶栏布局会变**：同样是秘密商店，金币图标的 x 一次是 828，一次是 908（右侧的红点和图标数量变了）。所以先用 `top/gold`、`top/skystone` 定位图标，再读右侧的数字。金币数字的读取宽度不超过天空石图标的位置。
2. **购买确认框和通用确认框不一样**：标题是「购买商品」，按钮是「取消」和「金币价格 + 购买」。内置 `confirm` 规则认不出它，原本会走遮罩兜底（返回键）。
   - 现在单独注册了 `shop_buy`，自动关闭时点取消。
   - 刷新框和退出游戏框的按钮完全一样，所以 `shop_refresh` 靠 OCR 文字「立即更新」区分。
3. **买完没有弹窗**：只有顶部飘过一条获得横幅（约 1.5 秒）；这一行变灰、显示 0/1，购买模板的 `max_diff` 不让它命中。金币数字会滚动，所以要求连续两帧读数一致。
4. **商店每小时自动刷新一次，过程是静默的**：没有弹窗，不扣天空石，列表换新并回到顶部。
   - 刷新计数看的是天空石读数差，不会把自动刷新误算成一次刷新。
   - 如果在扫描和点购买之间恰好自动刷新了，确认框里的名字或价格对不上，会点取消，并记一次失败。
5. **国服译名**：用户确认蓝色图标是「誓约」（不是我最初写的「圣约书签」）。
   - 为此加了按图标识别：`Target.icon`，在每行的物品图标框里匹配，图标模板由用户提供。
   - 名字或图标任一对上即为目标，价格核对照样生效。
   - 确认框里的名字只要和列表这一行一致就行（按图标认出的目标，名字可能和配置的不同）。
6. **任务开始时列表位置未知**：probe 时发现，用户之前在商店里滑到了底部，任务直接扫了底部视图，漏掉了顶部的 2 行。用户确认从大厅进店和刷新后列表都在顶部，所以只有「任务开始时已在商店里」才先滑到顶。
7. **确认框里商品名偶尔多一个字**：「烈风龙族士兵」读成了「烈风龙族士兵陶」，可能是物品框边缘被读进去了。名字匹配允许目标名是读数的子串，所以不影响判断；只做子串匹配，不做模糊匹配，宁可漏买也不买错。
8. **dry-run 默认开启**：误启动不会花钱，实跑必须显式传 `"dry_run": false`。B09 的 GUI 表单会显示这个开关。
