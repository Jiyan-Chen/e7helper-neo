### 反馈 1：竞技场并入日常收取
- **原话**：「自动打竞技场应该放入日常收取里，不用单独做一个模块」
- **原因**：B05 把竞技场 NPC 做成了单独的模块 `arena_npc`（单独的菜单页、设置、统计）。但打竞技场是每天的例行事，玩家希望和邮件、精灵之森、誓约召唤一起点一次「收一次菜」就做完，也能跟着「持续收菜」自动跑。
- **修改**：竞技场变成日常收取的第 4 项，`arena_npc` 模块取消。识别、核对和安全规则（旗帜读数差确认、补旗只用友情点数并核对选中项、自动战斗判断、战斗中不按返回键）原样保留。
  - 顺序：邮件 → 精灵之森 → 誓约召唤 → **竞技场**（最耗时的放最后）。做完回到大厅（结算点「确认」，其余界面点返回）。
  - 设置（表单）：新增「竞技场」（默认**开**）、「用友情点数补旗」（默认关，竞技场关掉时变灰）。演练开关对竞技场同样生效（只走到准备界面，不点开始 / 购买）。
  - 账本：补旗成功、或补旗框显示今天已经不能用友情点数时，记 `arena_buy`，当天旗帜用完后不再打开补旗框。
  - 结果语义的变化：原来竞技场「连续失败 3 次」「等结算超时」「读不出旗帜」算正常停止，现在按日常收取的规则算**这一项失败**（其他项照做，任务最后记为失败）；旗帜读数异常仍然立即停止整个任务。
  - 统计：日常收取的统计加上竞技场场数、胜场、用掉旗帜、补旗次数、花费友情点数。

### 反馈 4：「动态」里的红色 asyncio 报错
- **原话**：「把「动态」里那条红色 asyncio 连接断开报错也修掉，记成反馈 4。」（反馈 3 验证时我发现的）
- **原因**：浏览器刷新 / 关页、GUI 重连、引擎重启时，对端已经把连接重置了；Windows 的 Proactor 事件循环在 `_call_connection_lost` 里还要 `shutdown()` 这个 socket，抛 `ConnectionResetError: [WinError 10054]`。连接本来就要关，没有任何影响，但 asyncio 默认把它记成 ERROR，经引擎的日志桥接出现在 GUI「动态」里（还带一大段堆栈进 engine-stdout.log）。这是 CPython 在 Windows 上的已知行为，不是我们的代码出错。
- **修改**：
  | 文件 | 说明 |
  |---|---|
  | `engine/e7helper/api/app.py` | 新增 `quiet_connection_lost`：事件循环的异常处理，只忽略「`_call_connection_lost` 里的 `ConnectionResetError` / `ConnectionAbortedError`」（降成 DEBUG），别的异常照常交给默认处理；lifespan 启动时装到 uvicorn 的事件循环上 |
  | `engine/tests/test_api.py` | `test_quiet_connection_lost`（这两种被忽略；别的异常、别处的 ConnectionResetError 照常记 ERROR）；`test_lifespan_installs_loop_exception_handler`（服务启动后事件循环用的是它） |
- **验证**：
  - 复现脚本（scratchpad `repro_reset.py`：连上引擎后用 5 种方式突然断开——WS 握手后立即 / 0.3 秒后 RST、不读回复直接关、半关再 RST、HTTP keep-alive 后 RST，同时不停请求接口让引擎往外推数据；每种 5 轮，然后查 `/api/logs`）：
    - 修复前：断开 25 次，`/api/logs` 里 `_call_connection_lost` 报错 **30 条**，engine 日志里 30 段堆栈。
    - 修复后：断开 25 次，**0 条**，engine 日志里 0 段。
  - `pytest tests/test_api.py tests/test_flows_api.py tests/test_capture_api.py`：47 passed（含新加的 2 个）。
  - 开发版：改了引擎，要重启 `pnpm tauri dev` 才生效。

### 反馈 7：引擎关闭时挂住（顺带：断开太快会让 API 再也连不上）
- **原话**：「引擎关闭时等 WebSocket 挂住的问题也修掉，记成反馈 7。」（反馈 6 时我发现的：三个临时引擎收到 `/api/shutdown` 后停在 uvicorn「Shutting down」，一直不退）
- **复现**（scratchpad `repro_shutdown.py`：起临时引擎，连着 `/ws` 和 `/ws/frames`，再加一个握手后不读不写的连接，然后请求关闭，计时）：
  - 只有正常的连接（包括不回应关闭握手的）：0.3 秒内退出，WebSocket 收到 1012 关闭——**不是**单纯「等 WebSocket」。
  - 关闭前先用反馈 4 的 5 种方式突然断开 25 次：引擎**直接不再接受连接**（之后的请求都是「积极拒绝」），日志里是 `asyncio: Accept failed on a socket … WinError 64`。
- **原因**：两个都是 Windows 上 asyncio 默认的 Proactor 事件循环的毛病（CPython 3.13.13 实测）：
  1. 客户端在被 accept 的瞬间断开（浏览器刷新 / 关页 / 重连都可能），accept 报 WinError 64，Proactor 记一条 ERROR 后**把监听 socket 关掉**——整个 API 从此连不上，GUI 只能一直显示「正在重连」。
  2. 对端已重置的连接，Proactor 关它时 `shutdown()` 抛错（就是反馈 4 那条红字），后面的 `sock.close()` 和从 `asyncio.Server` 摘掉这个连接都被跳过；关服务时 uvicorn 等 `server.wait_closed()`，永远等不到——这就是挂住的原因（挂住的三个引擎日志里都有反馈 4 的那条报错，没挂住的都没有）。反馈 4 只把日志藏起来了，没解决这个。
- **修改**：
  | 文件 | 说明 |
  |---|---|
  | `engine/e7helper/cli.py` | uvicorn 配置提成 `server_config()`：事件循环改用 `asyncio:SelectorEventLoop`（没有上面两个问题；引擎不用 asyncio 子进程，Selector 在 Windows 上只缺这个）；`timeout_graceful_shutdown = 5` 秒兜底（GUI 退出 8 秒后会强杀引擎，5 秒在这之前） |
  | `engine/e7helper/api/app.py` | 反馈 4 的异常处理留着兜底，注释说明 |
  | `engine/tests/test_api.py` | `test_server_uses_selector_loop_and_graceful_timeout` |
- **验证**：
  - 复现脚本（断开 25 次后连着页面请求关闭），各跑 3 次：
    - 旧的 Proactor（临时改回去对比，测完已恢复）：2 次引擎在断开时就停止接受连接（`Accept failed`），1 次正常。
    - Selector：3 次都在 0.25–0.36 秒内退出（退出码 0），日志里 `Accept failed` / `Exception in callback` 都是 0 条。
  - `pytest tests/test_api.py tests/test_flows_api.py tests/test_capture_api.py`：48 passed。
  - 冻结版（安装包）走同一个 `serve`，改动一样生效；打包冒烟测试留到 B12 结束重新打包时一起跑。
