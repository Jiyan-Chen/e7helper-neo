### 配置 `ArenaNpcConfig`
| 字段 | 默认 | 表单 | 说明 |
|---|---|---|---|
| `buy_flags` | false | ✔ | 旗帜用完后用友情点数补旗（100 换 5 面，每天限一次；绝不用天空石） |
| `dry_run` | **true** | ✔ | 只导航到准备界面并决定模式，不点「快速对战」「战斗开始」「购买」 |
| `max_battles` | 0 | | 最多打几场，0 表示打到旗帜用完 |
| `prefer_quick` | true | | 优先快速对战，当天次数用完改打普通战斗 |
| `max_flag_buys` | 1 | | 每次运行最多补旗几次（游戏每天限一次，上限 1） |
| `friendship_keep` | 0 | | 友情点数保底 |
| `max_failures` | 3 | | 连续失败次数上限 |
| `battle_timeout` | 300 | | 一场普通战斗最长等待秒数 |
| `probe_dialogs` | false | | dry-run 时打开补旗框核对后点取消 |

内部字段用 `pydantic.json_schema.SkipJsonSchema` 隐藏，`config_schema()` 只有前两项，`run -c` 仍然可以传（用户：不需要给用户太多配置，引擎内部可以留接口）。

### 流程与安全规则
1. `wait_scene`（大厅 / 模式选择 / 交战对手页 / NPC页 / 准备界面 / 结算），按所在界面导航到 NPC 对战页。
2. 读顶栏旗帜（先定位 `top/flag` 图标，再读右侧「当前/上限」，连续两帧一致才采用）。
3. 旗帜 ≥ 1：
   - 「挑战」没亮就点第一行（用户：NPC 没有难度，只选第一行）；`tap_until("npc/challenge", 准备界面)`（挑战不消耗旗帜）。
   - 准备界面：优先快速对战；快速对战剩余次数读数为 0（或读不出）就点切换钮改成普通战斗，本次运行不再试快速。
   - dry-run 到这里记下「会用 X 模式挑战」，返回 NPC 列表并停止。
   - 点「快速对战」/「战斗开始」（只点一次，不用 `tap_until`）→ 等结算：
     - 普通战斗中：自动战斗图标连续 0.6 秒不动才点开（开启后一直旋转），点完至少 2.5 秒再判断，最多 4 次；
     - 战斗中不按返回键（会打开暂停菜单），只有网络异常立即重试，其他弹窗持续 10 秒才交给内置规则；
     - 战斗画面在动就 `progress()`，长战斗不会被判卡死；
     - 点了开始 8 秒后仍停在准备界面且按钮还在 → 认为点击被吞，记一次失败。
   - 结算：再等最多 1.5 秒认胜利字样（刚出现时还在发光动画里）→ 点「确认」回 NPC 列表（2 秒没反应补点，确认不消耗东西）。
   - **旗帜读数减少 1 才算一场**。读数不变（恰好回复了一面）只记警告；减少 2 以上或点击被吞却少了旗帜 → `ArenaAnomaly`，任务失败。
4. 旗帜 = 0：没开补旗 → 停止「旗帜用完」；开了补旗 → 点旗帜图标右上角的「+」打开补旗框：
   - 核对：左边是友情点数选项（`buy/friendship` 图标）、左边被选中（亮边框）、右边天空石**没有**被选中、消耗 100 换 5 面、持有 − 100 ≥ 保底；
   - 没选中友情点数时点一次左边选项再核对；任一项不符 → 点取消并停止；
   - 点「购买」→ 轮询旗帜读数直到变化 → **增加 5 才算补旗成功**；没变化 → 停止（可能今天已补过）；其他值 → `ArenaAnomaly`。
5. 无论正常停止、异常、急停还是超时，`finally` 里都会写统计。

## 过程中发现的问题与决策
1. **竞技场里好几个界面的标题都是「竞技场」**：模式选择、交战对手、NPC 页、准备界面都一样。所以内置 `arena` 加了模式卡片模板，只认模式选择界面；其他界面由本模块注册的场景区分。
   - 副作用：CLI `scene` 只加载内置场景，在这些界面上会显示「未知」（模块运行时没有问题）。
2. **进竞技场会弹「战斗记录」**（防守结果、段位变动），注册成 `arena_record`，点「点击关闭」。第二次进入时没有再弹。
3. **自动战斗图标**（用户纠正）：开启后图标是在**旋转**，蓝色光圈只是点击特效。判断方法改为「图标区域连续 0.6 秒不动 = 没开」。实测关闭时帧间差 0.3–0.7，开启后 20 以上。没开自动时战斗会停着等玩家选技能，画面本来就静，这个判断在实机上一次就生效了。
4. **补旗用的是友情点数**（100 换 5 面），不是书签；用户确认每天只能补一次。
5. **今天补过之后，补旗框会自动选中天空石**，「购买」按钮仍然亮着（左边显示「一天可购买1次 / N分后可购买」）。如果只看按钮就点，会花 30 天空石。模块点「购买」前会核对左边是友情点数且被选中、右边没被选中，所以会拒绝并点取消。这种情况已补成 fixture 和模拟器测试。
6. **旗帜为 0 时点「快速对战」会弹出同一个补旗框**（背景是准备界面）。模块不走这条路：先读到旗帜为 0，再点「+」补旗，这样补旗前后都在 NPC 列表上，读数 0 → 5 的核对不会和开始战斗的扣旗混在一起。万一开始时意外弹出这个框，规则会点取消，然后改走「+」。
7. **打完一场 NPC 列表会重排或整体换新，选中状态也会被清掉**。按用户意见只点第一行，不按名字找。
8. **两种结算界面布局不同**：快速对战的按钮在中间，普通战斗的按钮在右下角。按钮文字模板用同一个，检索区域覆盖下半屏。
9. **普通战斗结算刚出现时，点「确认」会被吞**（实跑时第一次没反应，6 秒后补点才成功）。确认不消耗东西，补点间隔改成 2 秒。改完后只跑了离线测试，没有再实跑。

## 录屏做法（采 fixture 用，脚本放在会话的 scratchpad，没有进仓库）
用户说「开始」后，在后台启动录屏脚本；用户说「好了」后，在输出目录里建一个 `STOP` 文件让它退出。脚本只截图，不点击：
1. 入口先调用 `isolate_native_stdout()`，然后 `connect()`；
2. 循环：约每 0.15 秒截一帧，和上一次保存的帧比缩略图差（`thumbnail` / `thumb_diff`）；差 ≥ 3 或距上次保存超过 1 秒才保存为 `<秒数>.png`，同时把 `default_detector().detect(frame)` 的结果写进 `log.txt`；
3. 目录里出现 `STOP` 就退出。

分析时先看 `log.txt` 里场景变化和帧差大的时刻，再把关键帧拼成联系表（缩到 533×300、3 列）查看，选中的帧直接复制成 fixture。一场 30 秒的普通战斗约 250 帧、300MB，用完可以删掉。

## 已知问题 / 后续
- **没见过失败结算**：NPC 太弱，两场都赢了。认不出胜利字样时记为「没认出胜利」，流程不受影响（仍然点确认、按旗帜计数）。
- **每日补旗的重置时间**：截图显示「23分后可购买」（02:36 截的，推测 03:00 重置），没有实测跨日。模块不记日期，靠补旗框的状态判断，所以不依赖重置时间。
- 快速对战每天 10 次，用完后的界面（0/10 时按钮的样子）没见过：读数为 0 或读不出时都改打普通战斗，切换失败也按普通战斗打。
- 长时间连续运行（例如补旗后连打 5 场）还没在实机上跑过，离线模拟已覆盖。
- fixtures 新增约 21MB，总计约 43MB。
