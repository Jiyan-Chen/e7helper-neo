## 过程中发现的问题与决策
1. **DLL 调试输出**：`external_renderer_ipc.dll` 静态链接了 CRT。`nemu_connect` 时往 stdout 打印，每次 touch 往 stderr 打印坐标，而且是缓冲输出，进程退出时才写出来。
   - 处理：入口调用 `isolate_native_stdout()`，把 fd 1/2 和 Win32 标准句柄永久指向 NUL，Python 输出改走复制的句柄（控制台下用 `_WindowsConsoleIO`，否则在 GBK 代码页下会乱码）。
   - Rich 固定使用 `legacy_windows=False`，并开启控制台 VT 模式。
2. **adb 后备不依赖 adbutils**：直接调用 MuMu 自带的 adb.exe，避免与系统里其他 adb 版本冲突。
3. **PyPI 很慢**：直连约 3KB/s，清华镜像不通，所以改用华为云镜像（约 4.6MB/s）。
   - uv 是用 `pip install --user -i <华为云>` 装的，没有改全局 pip 配置。
   - `uv.lock` 里锁定的是华为云镜像的 URL。
4. **Python 版本**：计划写的是 3.12，实际用的是本机已有的 3.13 x64（`requires-python >=3.12`），避免再下载一个解释器。
5. 测试 `tap 800 450` 时误点开了桌面上的 KernelSU 主页，只是打开、没有任何改动，已经用 HOME 键退回桌面。之后的测试都点在空白处 (1580,880)。

## 已知限制
- `nemu_get_display_id` 只做了封装，还没有接入。如果开启 MuMu 的“后台保活”，游戏可能在独立的 display 上，到时需要验证。
- 多实例只用一个实例实测过，多开的端口逻辑来自 MuMuManager 的输出，没有硬编码。
- `run` 命令目前直接执行模块。B03 之后会改由 runtime 调度（包括 task 互斥和急停）。
