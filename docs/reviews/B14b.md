## 最终方案

- 词表：训练集里选过 ≥ 30 次的 248 名（全量重训时 265 名），其余 UNK；训练时 2% 的英雄随机换成 UNK。

### 编码（`core/rta/encode.py`）
一场 = 17 个 token：`[CTX] [预禁 F1 F2 S1 S2] [选秀 1…10] [后禁：F 被禁的, S 被禁的]`，每个 = 英雄嵌入 + 类型嵌入（7 种）+ 位置嵌入（同一方两个预禁共用一个位置）；CTX 加双方段位档 + 开战规则（海外四条 / 无 / 国服「未知」）。0–4 互相可见、之后因果，**一次前向读出 12 个局面**（已选 n 手读 4 + n，后禁后读 16）。胜率一律是**先手方**赢的概率。选人标签：下一手，连选 2 名的回合两名各 0.5。

### 模型：Transformer + 因子分解机（混合结构）
- **胜率 logit = 因子分解机（强度 + 搭档 + 克制，宽部分）+ Transformer 的修正（深部分）**；选人头 = Transformer 输出 × 英雄嵌入的转置（共享权重）。随包的是 d = 128、3 层、4 头、λ = 1、k = 16，**66.5 万参数**。
- 损失 = 12 个局面胜率 BCE 平均 + λ × 10 个局面选人交叉熵平均；AdamW + 余弦退火，batch 512；按验证集的胜率损失（12 个局面平均）保存最好的一轮。随包模型训练时用的是 patience 4 的早停（第 28 轮停、最佳第 24 轮）；审核中改成默认跑满整个周期，见「审核中追加」。
- 校准：验证集上每个局面拟合一组斜率 + 截距（Platt 缩放），写进 `meta.json`。

### 和方案草稿不一样的地方（都是过程中按数据改的）
| 改动 | 原因 |
|---|---|
| 加了「Transformer + 因子分解机」混合结构（原方案只有纯 Transformer） | 纯 Transformer 怎么调都打不过因子分解机（测试集 n = 11 log loss 0.630–0.646 vs 0.624），而且**几乎用不上后禁信息**（n = 10 → 11 的 AUC 不涨）：后禁的英雄只在序列末尾出现一次，要靠注意力把它从这一方「减掉」，学得很慢。因子分解机显式去掉被禁的英雄。两者相加：宽部分学两两关系，深部分补上下文 |
| 早停从「胜率 + λ × 选人」改成只看胜率 | 选人那部分后期过拟合，总损失停了胜率还在变好（d = 64 混合结构第 31 轮停，第 37 轮 n = 11 还在降） |
| 温度缩放 → 每个局面的 Platt 缩放 | 共用一个温度时前几手偏自信、后禁后偏保守，互相抵消（n = 11 的 ECE 约 0.02）；分局面的温度把 ECE 降到 0.006，但 d = 128 的模型在 n = 11 还有整体偏移（验证集平均预测 0.494、实际 0.508），温度修不了，加截距后修好 |
| 网格从 8 个缩到 6 个纯 Transformer / 混合 + 2 个因子分解机 | 前两个纯 Transformer 明显落后后，把时间留给混合结构和基线调参 |
| 没写因子分解机的 numpy 推理后备 | 混合结构过了门槛，用不上 |

## 审核中追加（2026-10-26）：早停策略和 grokking
用户问：会不会出现 grokking，早停是不是该宽松一点。

**先看已有日志**：几个 run 的训练胜率损失一直在 0.636–0.645（日志里的值带着 dropout 和 UNK 替换），验证 0.653，没有把训练集背下来；标签是一场比赛的胜负，噪声很大；权重衰减只有 0.01。这三点和 grokking 的前提（先背下训练集、标签干净、强权重衰减长时间训练）都相反。但发现一个真问题：d = 64 的混合结构（50 轮上限）第 4 到第 21 轮验证损失原地 17 轮不动，学习率降到约 1.3e-3 以下后才从 0.6606 降到 0.6559。这是学习率退火，不是 grokking；patience 4–6 的早停在学习率还高时就开始计数，会停在平台上。

**按用户意见改**（`fit.py` / CLI）：
- 默认**跑满整个余弦周期**，按验证集保存最好的一轮；`--patience N` 打开早停，学习率降到峰值三成以下才开始计数（`patience_after`）。
- `--schedule constant`（预热后恒定学习率，grokking 实验用，排除退火的影响）、`--weight-decay`。
- 每轮在固定的 5 万场训练数据上用评估模式（不 dropout、不换 UNK）算一次胜率损失（`train_win_loss`），终端和曲线页（虚线点）都显示，用来看训练 / 验证差距。

|---|---|---|---|---|---|
| hy-d128-L3-lam1（随包的那个） | 30 轮、patience 4 | **0.65302** / 24 | — | **0.6166** / 0.7166 | |
| hy-d128-L3-lam1-e50 | 50 轮跑满 | 0.65371 / 26 | 0.6289 | 0.6181 / 0.7146 | 第 26 轮以后一直平在 0.6537–0.6547，训练子集一路降 |
| hy-d128-L3-lam0.5-e50-full-sched | 50 轮跑满 | 0.65303 / 24 | 0.6194 | 0.6178 / 0.7149 | 后半程过拟合：验证升到 0.6576，训练 / 验证差距从 0.020 拉大到 0.038 |

结论：d = 128 的模型容量够，学习率降下来后很快到底，再往后就过拟合；跑满周期没有带来提升。d = 64 上看到的平台是容量小、学习率高时的欠拟合。**随包模型不换**（测试集上仍然最好），不用重训和重新导出。默认跑满 + 保存最好一轮对两种情况都对，只是多花时间。

**grokking 实验**：纯 Transformer d = 64、2 层、λ = 1，恒定学习率 2e-3、权重衰减 0.1，120 轮（约 11.6 万步，49.9 分钟）。用纯 Transformer 是因为它有一个具体的「没学会」：用不上后禁信息（n10 和 n11 的 log loss 一样）。如果长时间训练加强正则能让它「顿悟」，这个差距会突然拉开。

|---|---|---|---|
| 1–20 | 0.6699 | 0.6618 | −0.0002 |
| 21–40 | 0.6669 | 0.6576 | 0.0000 |

- **没有出现 grokking**：第 40 轮以后验证损失平了，最好 0.6635（第 66 轮），比同样大小、余弦退火 30 轮的纯 Transformer（0.6603）还差；训练子集一直在 0.656 左右，训练 / 验证差距稳定在约 0.009（训练期和验证期日期不同，其中一部分是分布变化），从没背下训练集，没有 grokking 的前提。后禁信息 120 轮一直没用上。
- 局限：文献里的 grokking 有时要 10⁵–10⁶ 步；这次是 1.2 × 10⁵ 步。但训练集根本没被背下来，再跑下去出现的可能性很小。

## 审核中追加（2026-10-26）：模拟 BP 和冷门英雄外推
用户要用模型模拟一次 BP → 加了 `e7helper rta sim`（终端交互，开发用）：你选先手 / 后手，输入自己的预禁（对手的按训练快照里的预禁热度抽）；轮到你时列出「选了之后胜率最高」的 8 名（只往前看一步，不考虑对手回应）和「这一手大家常选」的 5 名，输入中文名或昵称，回车 = 第一个推荐；对手按选人头的前 8 名抽；选完给出双方各禁一名的 4 × 4 胜率矩阵（★ = 最坏情况下最好的后禁），对手按自己最稳妥的禁；最后汇总阵容和每一手之后的胜率。`--opponent manual` 时对手也由你输入（复盘真实对局）。

**发现的问题**：第一次用默认选项（一路回车）跑，一层贪心推荐的全是这一手几乎没人选的冷门英雄（卡瓦娜、休塔尔克、薇薇安、杀手可丽……，常见度 0.0%），模型把胜率一路推到 100%。而这些英雄在数据里**输多赢少**：薇薇安被选 100 场、选它的那方只赢 14%，休塔尔克 195 场 27%，卡瓦娜 57 场 35%。
- 拆开混合结构看：问题主要在**因子分解机的两两项**。例：后手第一手选卡瓦娜，它自己的强度几乎是 0（−0.03），宽部分却给出 −1.01（全来自和场上英雄的搭档 / 克制项），后手胜率算成 82%；Transformer 部分很稳（各候选 −0.29 ~ −0.63）。冷门英雄的这些向量只从几十到几百场里学，噪声大；几名叠在一起时噪声累加，胜率外推到 0% / 100%。冷门英雄的嵌入范数也偏大（平均 4.1，常用的 2.1）。
- 对真实对局的影响（测试集、后禁后，按这场里最冷门英雄在训练集被选过的次数分组）：

| 最冷门英雄被选过 | 场数 | 混合结构 log loss / ECE / \|logit\| > 2 的比例 | 因子分解机 log loss / ECE / \|logit\| > 2 |
|---|---|---|---|
| < 300 次 | 3,913（1.8%） | 0.6482 / **0.078** / 18.3% | 0.6168 / 0.049 / 12.1% |
| 300–1000 次 | 6,602（3.0%） | 0.6268 / 0.051 / 10.7% | 0.6245 / 0.038 / 7.7% |
| 1000–5000 次 | 49,173 | 0.6236 / 0.019 / 4.4% | 0.6310 / 0.021 / 3.3% |
| ≥ 5000 次 | 163,532 | **0.6133** / 0.006 / 2.7% | 0.6215 / 0.006 / 1.8% |

  带冷门英雄的约 5% 对局里混合结构明显过度自信（比因子分解机还差），常见英雄的对局里它更好；总体指标被那 95% 盖住了，门槛没查出来。B14c 的搜索会专挑模型高估的地方，这个问题必须先解决。
- **临时处理**（只在模拟里）：推荐的候选只取这一手常见度 ≥ 0.5% 或排前 40 的（用选人头做先验，B14c 的搜索本来也要这样）；加了以后推荐都是正常的英雄，一路回车的那局最终 66.7%。
- 词表门槛对应的英雄数（训练集 / 全部）：≥ 30 次 248 / 265、≥ 300 次 164 / 185、≥ 500 次 145 / 164、≥ 1000 次 129 / 139、≥ 2000 次 107 / 127（e7rtabot 只覆盖约 120 名）。
