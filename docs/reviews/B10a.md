# B10a 审核记录：弹窗补漏——断线自动重进

状态：✅ 已通过 · 日期：2026-10-19（同日审核通过）

## 起因
B10 真机验证时，安装版连上 MuMu，游戏正停在「与服务器的连接中断，将返回游戏初始界面。/ 点击关闭」框上。冻结版和源码版的 `e7helper scene -f` 都认成「未知」：这个弹窗从来没登记过，任务因此认不出大厅。

## 范围（开工时和用户确认）
- 单独记为小块 **B10a**，不并入 B10 的审核。
- 处理方式：用户选**自动重连**——「重连过程中只需要点击屏幕继续，不需要输入凭证」。所以不抛 `PopupError` 让任务停下，而是自动点「点击关闭」、关公告、点标题画面，直到回到大厅。
- 真机实测：用户用手机登录同一账号，把模拟器挤下线，触发了真实的断线框。

## 实测的重进流程（2026-10-19，MuMu 1600×900）
断线框（压在大厅 / 召唤界面上）→ 点「点击关闭」→ 标题画面弹出**登录公告窗**（最新消息 / 活动专区 / 常见问答）→ 点右上角 X → 标题画面「连接中……」15–26 秒 → 出现「轻触画面开始」（协议勾选框保持勾选）→ 点这行字 → **黑屏**约 16–18 秒 → 大厅。当天已经登录过，没有签到奖励等额外画面。

## 已知问题 / 注意
- **重进后任务进度丢失**：游戏回到大厅，任务之前所在的界面没了。任务在别的界面里等模板 / 场景时会超时失败（游戏本身已经恢复，下次运行正常）；只有 `tap_until` 导航那一步能自动接上。没有做「重进后整个任务从头再跑」，因为重跑会重置天空石等预算计数，有多花资源的风险。
- 重进只在 `dismiss_popups` / `wait_scene` / `tap_until` 里发生；`ctl.wait(模板)` 不处理弹窗，断线时会等到超时。
- 每天第一次登录可能出现签到 / 活动奖励等画面，这次没遇到，没有登记。认不出时 `_wait_reload` 等满 120 秒抛 `PopupError`，任务失败。
- 协议勾选框如果没勾，点「轻触画面开始」会弹出协议提示，同样会超时失败。不会自动去勾选或点协议链接。
- 冷启动（游戏没在运行）不在范围内：开屏、健康提示等画面不是弹窗，任务的 `wait_scene` 会照常超时。
- 本 worktree 基于 B09 的提交，B10 的改动不在这里。合并时 `docs/ROADMAP.md` 的 B10 / B10a 两行可能冲突。
- 整个重进约 55 秒，计入任务的总超时。
