## 过程中发现的问题与决策
1. **弹窗遮罩下按钮仍然得高分**：`TM_CCOEFF_NORMED` 对亮度和对比度的线性变化不敏感，被遮罩压暗的「购买」「立即更新」「返回」都能得 1.000 分。
   - 处理：新增 `max_diff`，即命中位置与模板的平均像素差上限。实测正常亮度时 ≤ 8.3，压暗后 ≥ 62；可点击的 `back` / `buy` / `refresh` 设为 30。
   - 顶栏图标和标题不设 `max_diff`，有弹窗时仍可识别（场景识别需要）。
2. **RapidOCR 的调用参数会留在实例上**：上一次传 `use_det=False`，下一次没传时仍然不做检测。现在每次调用都显式传 `use_det` / `use_cls` / `use_rec`。方向分类关闭，因为游戏文字都是横排。
3. **OCR 对全角/半角标点不稳定**：同一个「？」在不同裁剪下会输出全角或半角。新增 `normalize_text`，比对文字时先归一化。
4. **共用模板放在 `common`**：返回键、顶栏图标、通用弹窗按钮、大厅入口给 B03 的场景/弹窗识别用。`Vision.for_module(id)` 先查模块自己的模板再查 common，`common` 这个 id 保留。
5. **模板截取策略**：图标只截内部（避开半透明边缘和「+」角标），因为背景会随界面变化。同一个天空石模板在大厅（位置 1009）和商店（位置 1014）都能命中，分数 0.991 / 1.000。
6. **`uv add` 写入了镜像配置**：带 `UV_DEFAULT_INDEX` 执行 `uv add` 时，uv 在 `pyproject.toml` 里加了 `[[tool.uv.index]] url=华为云, default=true`。之后不设环境变量也会走镜像，和 B01 决定的「uv.lock 保留镜像 URL」一致。我暂时保留了，需要你决定（见下文）。

7. **框选窗口报错 `namedWindowImpl ... not implemented`**（用户审核时发现）：`rapidocr` 依赖 `opencv-python-headless`，它和 `opencv-python` 都往同一个 `cv2/` 目录装文件，后装的无界面版覆盖了带界面版。匹配和 OCR 不受影响，只有 highgui（`selectROI`）不可用。
   - 处理：`pyproject.toml` 的 `[tool.uv] override-dependencies` 把 headless 的标记设成永不安装，rapidocr 改用 `opencv-python`（API 相同）。
   - 重新 `uv sync` 后，`cv2.getBuildInformation()` 显示 `Win32 UI: YES`，窗口可以正常创建。
   - 新增回归测试 `test_opencv_has_gui`。

## 已知限制
- `capture` 的弹窗框选（`cv2.selectROI`）需要人工操作，我这边只验证了窗口能创建、`--rect` 路径能用。窗口标题只能是英文，因为 highgui 不支持中文。
- fixtures 只覆盖大厅和秘密商店。这次商店里没有刷出圣约书签/神秘奖牌，这两个商品的模板留到 B04 采集。
- 截图都来自 1600×900 原生分辨率。1280×720 / 1920×1080 的测试是把截图缩放后模拟的，不是真机在该分辨率下的画面（游戏 UI 在不同分辨率下可能会微调布局）。
- 全屏彩色匹配约 130ms，模块应尽量给模板设检索区域，或使用 `--gray`。
- 大厅的模板是基于当前大厅背景（夏日海滩）截的文字部分；换了大厅背景后分数可能下降，B03 做场景识别时需要再验证。
- fixtures 一共约 5.3MB，会进 git。
